# 계정 삭제 운영 (#16)

> 2026-10-18 후속: 운영자 요청에 따라 소규모 베타 완료 기준을 [베타 운영 기준](beta-readiness.md)으로 재조정했습니다. 아래는 과거 구현·검증 이력이며, 현재 남은 범위는 해당 문서와 후속 #49/#50/#51을 따릅니다.

## 이용자와 관리자 흐름

1. 이용자가 로그인 후 내 정보 → 계정 삭제 요청에서 확인 문구를 입력한다. 대상은 현재 Google 계정 및 연결된 Google/Sites 프로필 전체다. 닉네임이나 이메일을 입력해 타인을 지정할 수 없다.
2. 문의 항목에서 **완료 조회 코드 받기**를 누른다. 원문 코드는 브라우저 localStorage에 저장하며 서버에는 SHA-256 해시만 남는다. 코드를 복사해 보관할 수 있다. 발급하지 않은 요청은 관리자가 실행할 수 없다.
3. 관리자는 `/admin/inquiries`의 삭제 요청에서 **삭제 대상 미리보기**로 연결 프로필, 삭제/익명 처리 건수를 확인한다. 확인 문구를 입력하고 명시적으로 실행한다.
4. 실행 성공 시 문의가 처리 완료로 닫히고 로그인 세션이 폐기된다. 이용자는 `/account-deletion`에서 로그인 없이 코드로 결과를 확인한다. 코드는 발급 후 90일, 실행 시점부터 다시 90일간 유효하다. 결과 API는 상태와 처리 시각만 반환한다.
5. 실행 전 이용자는 자신의 요청을 취소할 수 있다. 취소·완료된 삭제 요청은 일반 답변 기능으로 다시 열거나 수정할 수 없다.

이 기능은 운영자가 요청한 특정 계정만 처리한다. 배포나 마이그레이션 자체로 기존 사용자가 삭제되지 않는다. 임의 운영 계정으로 테스트하지 않는다.

## 데이터 처리 범위

| 대상 | 실행 결과 |
| --- | --- |
| Google 계정 정보·세션, 연결 프로필·이전 연결 증빙 | 삭제. 같은 Google 계정 재가입 시 새로운 임의 게임 ID 사용 |
| 프로필·꾸미기·구매·가구·집·돌봄·골드·개인 도전·오늘의 단어·칭호 | 연결된 계정 소유분 삭제 |
| 본인 방 플레이·대화·그림·힌트·관전·아이템 보유 | 연결된 참가자 소유분 삭제 |
| 방·공유 라운드 | 유지. 탈퇴자가 방장이면 남은 참가자로 이전, 없으면 방 보관 |
| 방 참가자·공유 아이템 이력 | 표시 이름과 계정/토큰 연결 제거, 비활성 참가자 자리만 유지 |
| 친구·초대·방문 관계 | 탈퇴 계정이 연결된 관계만 제거 |
| 문의 | 본인 문의 삭제. 실행 요청은 원문·이름·계정 연결 제거 후 처리 증빙만 유지 |
| 해당 계정 신고 | 타인의 신고 행은 유지하되 대상 이름·증거·상세와 관련 조치 사유를 제거. 신고자/대상 식별은 익명 식별로 교체 |
| 독립 게스트·타인의 프로필/게임/재화 | 삭제하지 않음 |
| 타인이 글에 쓴 언급, 미연결 게스트 명의의 과거 신고 | 자동 동일인 추정 없이 별도 검토 |
| 기존 백업·외부 제공자 로그 | 즉시 삭제 범위 아님. 별도 보존 확인 필요 |

재생성 방지용 `deleted_identifiers`에는 기존 계정/참가자 식별자가 남는다. 원래 식별자가 Google 기반일 수 있으므로 완전한 비식별 정보라고 간주하지 않는다. 이름·이메일·토큰·삭제 요청과의 매핑은 담지 않으며 일반 API에 공개하지 않는다. 감사 테이블에는 요청 번호·처리자·시각·건수만 보관하고 UPDATE/DELETE를 차단한다. 이 최소 정보와 백업의 최종 보관 기간은 별도 운영 정책으로 확정해야 한다. 법률 준수를 보증하는 문서는 아니다.

## 안전장치

- 관리자 권한을 API에서 검증한다. 관리자 프로필이 연결된 계정 및 자기 계정은 실행 불가.
- 미리보기는 관리자에게 귀속된 무작위 토큰으로 저장하고 5분 후 만료한다. 이름/채팅 원문은 미리보기 저장소에 복제하지 않는다.
- 연결 범위·요청 revision·행 수·데이터 revision이 달라지면 실행을 거부한다. 다른 게임 변경으로 revision이 바뀐 경우도 보수적으로 재확인을 요구한다.
- 삭제·방장 이전·익명 처리·세션 폐기·완료 기록은 한 D1 batch 트랜잭션이다. CHECK 실패나 중간 오류 시 전부 롤백한다.
- 요청 번호의 감사 기록 고유키로 중복 실행을 막는다. 응답 유실 후 재시도는 같은 완료 결과를 반환한다.
- DB 트리거로 삭제된 소유자의 지연 INSERT/UPDATE 및 이전 프로필 재연결을 차단한다. 재가입은 이전 식별자를 재사용하지 않는다.
- 최대 20개 연결 프로필·100개 참가자 범위를 지원한다. 초과 시 일부만 삭제하지 않고 거부한다. 별도의 검증된 대량 처리 절차가 필요하다.
- 만료 미리보기/조회 코드는 후속 미리보기/코드 발급에서 정리한다. 독립 정기 청소 작업은 아직 없다.

## 테스트와 배포

`tests/account-deletion.test.mjs`는 별도 메모리 SQLite에 전체 마이그레이션과 가상 사용자만 넣어 검증한다. 타인 플레이 보존, 공유 방 유지, FK가 있는 구매 삭제, 이전 연결 차단, 실패 롤백, 동시 실행, stale/cancelled/expired 요청, 권한, 로그인 없는 결과 조회를 포함한다.

새 마이그레이션: `drizzle/0030_account_deletion.sql`. 기존 데이터 UPDATE/DELETE 없이 테이블·트리거만 추가한다. 운영 DB에는 이번 PR 작업 중 적용하지 않았다. `deploy-schema.json`도 기존 운영 기준을 유지한다.

머지 전 순서:

1. 운영 백업과 현행 배포 복구 지점을 확보한다.
2. 운영자 승인 후 0030을 적용하고 기존 테이블 건수가 변하지 않았음을 확인한다.
3. 적용한 SQL 해시를 deploy-schema.json에 반영한 후 배포한다. 현재 PR 그대로는 스키마 배포 가드가 자동 배포를 막는 것이 정상이다.
4. 운영 테스트는 별도 승인받은 폐기 가능한 테스트 계정으로만 한다. 실제 사용자 요청은 범위 검토 후 개별 실행한다.

실패 트랜잭션은 자동 롤백된다. **성공한 삭제는 코드 롤백으로 복구되지 않는다.** 백업 전체를 복원하면 삭제 계정이 부활할 수 있으므로 삭제 감사/재생성 방지 목록을 다시 적용하는 복구 절차가 필요하다. 구버전으로 돌아가도 tombstone 트리거는 제거하지 않는다.

## 2026-10-18 운영 기준 보강 (#16)

운영자가 승인한 기준: 만 14세 이상 자기 확인, 채팅·그림 90일, 완료 문의·신고 완료 후 365일, 접속 표시 30일, 수동 백업 30일. 첫 플레이 화면에서 자기 확인을 받으며 생년월일·신분증은 받지 않는다. 브라우저의 자기 확인은 법정 연령 인증을 대체하는 기술적 신원 증명이 아니다. 실제 미만 이용을 확인하면 이용·처리를 중단하고 문의를 통해 조치한다. 미성년 이용·국외 처리에 대한 법적 적정성은 운영자 검토 대상으로 남긴다.

`/admin/operations`는 관리자에게 원문·이메일·식별자 없이 기간이 지난 건수만 표시한다. 기존 게임·재화·해금·집·회원 기록을 변경하지 않는다. 콘텐츠 만료 정리는 미리보기만 제공한다. 보관 정책을 소급해 원문을 일괄 삭제하지 않는다. 공지와 예외 검토 후 별도 실행 구현/승인이 필요하다.

Worker Cron은 매일 UTC 18:17(한국시간 03:17) 만료된 google_sessions/deletion_previews/deletion_receipts/safety_rate만 테이블별 최대 500개 정리한다. 유효한 세션과 삭제 감사·재생성 방지 식별자는 보존한다. 잘못된 시계·DB 오류에는 정리를 중단하며 트랜잭션을 롤백한다. 신규 SQL/운영 마이그레이션은 필요하지 않는다.

### 친구·집 공개 범위 확인

- 수락한 친구만 접속 상태/참여 가능한 방을 확인하며, 비밀번호 방 진입은 별도 서버 비밀번호 검증을 거친다.
- 집 방문/도장은 accepted 친구 관계를 서버에서 확인한다. 차단 관계는 Worker 경계에서 방문·초대·친구 요청을 거절하고 친구 목록에서 숨긴다.
- 공개 방에서 같은 사람을 완전히 배제하는 기능은 아니다. 개인 이메일과 내부 계정 키는 공개 프로필에 반환하지 않는다.
- 기존 `tests/safety.test.mjs`, `tests/home-life.test.mjs`, `tests/room-password.test.mjs`의 관계·서버 권한 테스트를 전체 검사에 포함한다.

### 배포 상태 정정

PR #42의 0030은 2026-10-18 운영 백업 후 적용했고 기존 49개 테이블 건수가 같음을 확인했다. deploy-schema.json은 0030까지 반영됐다. 위의 ‘이번 PR에서 미적용’ 문장은 당시 PR 준비 시점의 기록이며 현재 운영 상태가 아니다.

### OAuth 및 외부 제공자 운영 확인

코드는 openid/email/profile만 요청하며 mail/Drive 접근을 요청하지 않는다. Google 콘솔의 Audience 공개 상태, Branding의 서비스명/문의/개인정보처리방침, 웹 클라이언트 반환 주소 https://play.jamopop.workers.dev/auth/google/callback 를 콘솔에서 확인해야 한다. 코드 테스트만으로 콘솔 설정 완료라고 판단하지 않는다.

공식 참고: [Google 공개 운영 상태](https://developers.google.com/identity/protocols/oauth2/production-readiness/overview), [D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/). 무료 요금제의 D1 복구 가능 기간은 수동 백업 30일 정책과 다르다. 제공자 로그와 Time Travel의 기간을 앱 코드가 변경한다고 안내하지 않는다. 수동 백업 파일 만료는 scripts/backup-inventory.mjs로 경로·건수만 비공개 확인하고 실제 파일 삭제는 운영자가 수행한다.

### Google 콘솔 실제 확인 (2026-10-18)

jamopop 프로젝트의 웹 클라이언트에서 승인된 출처 https://play.jamopop.workers.dev 와 반환 주소 /auth/google/callback 일치를 확인했다. Branding에 비어 있던 홈페이지·개인정보처리방침·약관 URL을 실제 서비스 링크로 저장했고 저장 완료 표시를 확인했다. 승인 도메인은 jamopop.workers.dev다. Audience는 여전히 외부/테스트 중이다. 공개 게시 전환과 필요한 Google 도메인·브랜드 검증은 운영자 인수로 남긴다. 민감 권한을 새로 추가하지 않았다.
