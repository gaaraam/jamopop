# 콩알이의 집 / 비밀번호 방 / 희귀 스킨

## 사용자 기능

- `/home`: 내 집 / 프로필·기록. 기존 계정, 캐릭터, 전적, 게스트 기록 연결은 유지.
- 내 집: 가구 선택 → 빈 자리 클릭 또는 가로·세로 슬라이더 → 반전/보관 → 배치 저장. 취소 시 마지막 저장본 복원. 저장 전 이탈 경고.
- `/shop?category=home`: 가구·소품 8종(기본 러그 무료, 구매 7종). 같은 골드 지갑으로 영구 구매, 각 종류 한 개 소장. 캐릭터·카드 장착과 독립.
- 희귀 캐릭터 스킨 6종: 달의 정원사 토콩 1500G, 오로라 구미호 폭콩 1800G, 별사탕 왕자 냥콩 1600G, 구름 위 낮잠 곰콩 1200G, 진주빛 인어 펭콩 1500G, 꼬마 용기사 개굴콩 1800G. 기존 캐릭터 해금 조건 유지.
- 새 방 생성 때만 비밀번호 선택. 기존 방은 공개 유지. 초대 링크/대기실/관전 모두 최초 입장 시 확인. 기존 참가자 재접속 및 사이트 관리자는 재입력 불필요. 저장은 salted PBKDF2 SHA256. IP·방별 분당 10회 검증 제한.

## 데이터 보존과 검증

새 테이블 2개와 rooms nullable 컬럼 1개만 추가한다. plays, members, profiles, 기존 구매를 변경하거나 초기화하지 않는다. 가구 구매는 skin_purchases 원장과 기존 BALANCE_SQL을 공유한다. 가격은 서버 카탈로그로 결정하고 동시·중복 구매는 PK/단일 SQL로 한 번만 차감한다.

집 저장은 로그인 계정으로만 처리하며, 소유하지 않은 가구·알 수 없는 ID·중복·범위 밖 좌표는 거절한다. revision 조건부 갱신으로 여러 탭에서의 덮어쓰기를 방지한다. 저장 실패 시 편집 내용은 화면에 유지한다. 기본 러그는 무료 소유로 취급한다.

## 배포 전 필수 단계

이 PR은 운영 DB를 변경하지 않았다. `deploy-schema.json` 역시 고의로 갱신하지 않았다. 따라서 현 상태에서는 배포 가드가 차단한다. **운영 DB 준비 전 병합/배포하지 않는다.**

1. 운영 D1의 복원 지점/백업을 확인한다.
2. 운영 DB에 `drizzle/0025_room_passwords.sql`, `drizzle/0026_kongal_homes.sql`을 순서대로 한 번 적용한다. 기존 배포와 호환되는 추가형 변경이다. 0025는 재실행 불가하므로 먼저 rooms 컬럼과 테이블 존재 여부를 조회한다.
3. 적용 결과(rooms.password_hash, room_join_attempts, kongal_homes)를 확인한 후 두 SQL 파일의 SHA256을 `deploy-schema.json`에 추가한다. 기존 항목은 수정하지 않는다.
4. PR을 ready로 전환하고 리뷰/병합한다. Cloudflare 빌드가 테스트와 배포를 수행한다.
5. 새 공개 방·잠금 방 입장, 집 배치 저장/새로고침, 가구 구매 후 잔액 확인. 이상 시 이전 앱 빌드로 롤백하며 추가 스키마와 기록은 유지한다.

집 방문/타인 공개, 동일 소품 여러 개 구매, 집 확장은 이번 범위에 포함하지 않는다.
