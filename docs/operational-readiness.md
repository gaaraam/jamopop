# 운영 안정성 점검 (#17)

## 측정과 개인정보

Worker 경계에서 API/로그인 요청의 route 분류·HTTP 상태·응답 준비 시간·DB 호출 수·확인 가능한 rows_read/rows_written을 구조화 로그로 남긴다. URL 쿼리, 요청/응답 본문, 헤더, IP, 계정, SQL, 인증 코드, 단어·정답·채팅을 기록하지 않는다. 미등록 경로는 `/api/other`로 합쳐 경로에 숨은 식별자도 남기지 않는다.

AsyncLocalStorage로 동시 요청의 집계를 분리한다. `first/raw`는 결과 계약을 바꾸지 않고 행 수를 알 수 없는 호출로 센다. `batch`는 문장별 meta를 집계한다. 알 수 없는 행 수는 0건 처리됐다는 뜻이 아니다. JSON 응답 준비까지의 시간이며 전송 완료·브라우저 표시 지연은 포함하지 않는다.

관측 설정: `head_sampling_rate: 0.1`, 자동 invocation 로그 끔. 집계 로그는 표본이며 청구서·전체 요청량을 대신하지 않는다. 전체 요청량·CPU·DB 비용은 Cloudflare의 Worker/D1 지표로 확인한다. 게임·계정·개인 도전·오늘의 단어·운영 API의 기존 예외 로그에서 원본 Error 객체를 제거해 D1 오류에 포함될 수 있는 SQL·바인딩 값을 출력하지 않는다. 프레임워크·제공자 자체 예외 로그는 별도 운영 점검 범위다.

## 경보 기준

`node scripts/check-operations.mjs /비공개/metrics.jsonl`

20개 이상 표본에서 5xx 비율 >1%, p95 >1500ms, 429 비율 >5%를 각각 경보로 반환한다. 출력에 개인정보 원문을 넣지 않으며 경보 시 종료 코드 2. 표본 부족은 정상 확인을 뜻하지 않는다. 운영 호출 원문을 이슈에 붙이지 않는다.

**이 스크립트는 외부 알림을 자동 전송하지 않는다.** Cloudflare 알림 수신처·요금제별 사용량 경보를 연결하고 실제 경보 수신을 확인해야 #17의 알림 인수 조건이 충족된다. 기존 게임 운영과 관계없는 메시지를 임의로 발송하지 않는다.

## 격리된 동시 접속 검증

```sh
npm run build
npm run db:local
npm start -- --port 5260
node scripts/load-smoke.mjs http://127.0.0.1:5260 10,50,100 /tmp/load-results.json
```

`npm start`의 기존 기본 포트 인자와 충돌하면 `node_modules/.bin/wrangler dev --config dist/server/wrangler.json --local --persist-to .wrangler/state --ip 127.0.0.1 --port 5260 --inspector-port 0`를 사용한다. 항상 DB는 합성 로컬 데이터를 사용한다. 기본 load-smoke는 http localhost만 허용한다. 아래의 고정된 보호 스테이징 주소는 별도 QA 키·healthz 확인을 거친 경우에만 허용하며 운영 주소는 거부한다.

시나리오: 방마다 최대 10명의 가상 이용자 생성 → 동시 진행판 조회 → 동시 첫 제출 → 동일 expected 값 재전송 → 각 참가자의 한 줄만 저장됨과 새 조회 복원 확인. 실제 방 정원은 40명이며 50/100명을 한 방에 넣어 정원을 우회하지 않는다. 방 목록 조회, 장시간 채팅, Google 외부 인증 지연, 모바일 네트워크, CDN·원격 D1 위치·플랫폼 요금제 제한은 이 로컬 시험에 포함되지 않는다.

2026-10-18 로컬 측정(해당 개발 머신·한 번의 실행):

| 동접 / 방 | 제출 p50 / p95 | 진행판 조회 p50 / p95 | 중복·복원 |
|---|---|---|---|
|10 / 1|78 / 78ms|132 / 132ms|모두 1회 저장|
|50 / 5|186 / 272ms|682 / 700ms|모두 1회 저장|
|100 / 10|441 / 590ms|1508 / 1531ms|모두 1회 저장|

원본 합계: [가상 데이터 측정](qa/p0-local-load-20261018.json). 실제 사용자/방 식별자는 포함하지 않는다. **운영 100명 수용 보장이 아니다.** 원격 스테이징에서 장시간 10→50→100 단계로 측정하고 비용·오류율을 확인한 뒤 실제 공개 동접 한계를 정한다. 이번 데이터만으로 WebSocket 전환을 결정하지 않는다.

## 복구와 점검 리허설

`node scripts/restore-rehearsal.mjs`

모든 마이그레이션을 적용한 별도 파일 DB에 가상 프로필·방·참가자·삭제 감사·재생성 방지 식별자를 저장한다. 일관된 백업 생성 → 기본 파일 제거 → 백업 복원 → 전체 테이블 값 동등 비교·integrity_check → 삭제 프로필 재생성 거부를 검증한다. 운영 DB나 백업 파일을 읽거나 수정하지 않는다.

검증 결과: 51개 사용자 테이블의 행 동등, integrity=ok, tombstone 차단 유지. 이는 SQLite 파일 복구 리허설이며 **원격 D1 Time Travel 복구 실험과 다르다.** 원격 복원은 독립 스테이징 DB에서 먼저 수행한다. 실제 삭제 이후의 과거 백업을 복원하는 경우 최신 삭제 감사·재생성 방지 정보를 재적용하고 원문 부활 여부를 점검해야 한다.

코드 롤백: Cloudflare Deployments에서 이전 Ready 버전으로 되돌린다. 스키마·운영 데이터는 코드 롤백으로 되돌아가지 않는다. 추가 스키마를 제거하지 않는다. `MAINTENANCE_MODE=on`은 쓰기 요청을 503/Retry-After 60으로 멈춘다. 먼저 공지하고 저장 중인 요청을 확인하며, 게임 입력을 임의로 지우지 않는다. 완료 조회·문의 등을 계속 허용해야 하는 경우 전체 쓰기 점검 모드 사용 전에 운영 방식을 결정한다.

공식 문서: [Workers Metrics](https://developers.cloudflare.com/workers/observability/metrics-and-analytics/), [Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/), [D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/).

- 원격 격리 환경의 장시간 부하/비용 측정과 실제 운영 한계 확정
- 실제 오류/사용량 경보 수신

위 항목은 로컬 자동 검사나 코드 제공만으로 완료 처리하지 않는다.

## 실제 Cloudflare 격리 시험과 복구 (2026-10-18)

`jamopop-qa-p0` Worker와 별도 D1에 전체 스키마·가상 참가자만 배치했다. 운영 DB/Google 로그인 키를 연결하지 않았으며 `QA_ONLY=1` + 별도 비공개 QA_ACCESS_TOKEN을 요구한다. 비인증 /healthz 404, 인증 요청의 qa=true를 확인했다. load-smoke는 이 고정 스테이징 주소에 한해서 환경변수 키와 qa=true 확인 후 허용한다. 키는 저장소·리포트에 쓰지 않는다. 스테이징 테스트용 시드/배포 설정에 실제 운영 ID를 복사하지 않는다.

최초 순차 10/50/100 시험에서 100명 입장 중 JSON 503을 한 차례 받았다. 해당 호출의 원인 로그는 확보하지 못했으며 원인과 해결을 주장하지 않는다. 로그 수집을 켠 별도 100명 재실행은 성공했고 제출 p95 2743ms, 진행판 조회 p95 5778ms였다. 원격 대기 시간을 줄이기 위해 partyState의 독립 조회를 병렬화하고 일반전은 공통 만료 전 expirePlays UPDATE를 건너뛰었다. 아이템전은 개인 만료가 앞당겨지므로 기존 만료 검사를 유지한다. 서버 제출 시점의 만료·중복·권한 검증은 유지한다.

동일 스테이징의 후속 10/50/100 시험도 성공했으며 각 이용자의 한 줄만 저장됨과 재조회 복구를 확인했다. [후속 원격 결과](qa/p0-remote-optimized-20261018.json), [변경 전 별도 100명 결과](qa/p0-remote-load-20261018.json). 한 번씩 측정한 표본이므로 성능 개선률을 일반화하지 않는다. 100명 단계는 여전히 응답이 느리며 안정적 운영 수용량으로 승인하지 않는다. 공개 베타는 제한된 소규모로 관찰하고 장시간 운영 부하/요금 한계를 추가 확인한다.

Worker 실시간 로그에서 원문을 제외한 구조화 API 이벤트 713개를 추출해 검사했을 때 지연 경보와 종료 코드 2를 받았다(p95 5386ms, 해당 표본의 5xx/429는 0). **이는 검사 도구가 경보를 감지했다는 증거이며 외부 이메일·메신저 수신 증거는 아니다.** 추적 원본은 요청 헤더 등 기술 정보가 포함될 수 있어 비공개 임시 파일로만 다루고 공개하지 않는다.

복구 리허설: 가상 tombstone/감사를 넣은 D1 bookmark를 확보하고 그 이후 표식을 추가했다. 해당 bookmark로 원격 Time Travel 복원 후 5개 핵심 테이블(방·참가자·플레이·tombstone·감사) 건수가 동일하고 이후 표식이 사라졌음을 확인했다. 복원 후 삭제된 식별자로 프로필 생성 시 ACCOUNT_DELETED로 거절됐다. Worker도 이전 QA 키 포함 버전으로 롤백 → 인증 healthz 정상/비인증 404 확인 → 검증 후보 버전 복귀를 완료했다. 운영 play Worker와 운영 D1에는 이 복구/롤백을 수행하지 않았다.

남은 인수는 실제 사용량/비용 경보 수신, 장시간 원격 시험·공개 규모 확정, 최초 일시 503의 추가 재현/관찰이다. 자동 검사와 일회성 성공으로 이슈 전체를 닫지 않는다.
