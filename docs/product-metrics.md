# 제품 지표 1차 — #22

## 목적과 범위

참여 버튼을 누른 사람만 측정하는 방식은 표본이 적고 치우칠 수 있어 사용하지 않는다. 별도 참여 클릭 없이 서비스 자체의 게임별 진입·첫 조작·완료·재도전 횟수를 집계한다. 외부 분석 도구, 광고 추적, 회원별 행동 프로필은 추가하지 않는다.

대상은 방 대전·연습·스피드전·오늘의 단어·단어 도전·콩알 탈출·자모 쏙쏙·자모 톡톡이다. 첫 화면·대기실·개인 도전 목록의 진입도 센다.

| 이벤트 | 기준 |
| --- | --- |
| view | 실제 화면/복원 상태가 로드됨. 같은 탭 안의 동일 판 재조회는 중복 방지 |
| start | 진행 중인 판 확인. 복원한 진행 중 판과 방의 시작 대기 시간을 일부 포함 |
| first_action | 로드 뒤 첫 유효 이동/타일 선택 또는 서버가 수락한 첫 제출 |
| complete | 위 첫 조작을 확인한 동일 판이 성공·실패·시간 종료·포기로 바뀜 |
| retry / next | 직접 플레이한 뒤 같은 판 재시작/다른 판 선택. 방 모드는 다음 라운드를 관찰한 시점 |

완료율 = 같은 측정 판 안에서 start와 first_action이 확인된 complete / first_action. 복원한 완료 결과·되돌린 뒤 다시 끝낸 결과는 새 완료로 세지 않는다. 미완료 이탈을 실패로 단정하지 않는다. 입력 글자·사전 오류·조작별 이벤트·폴링·관전은 제외한다.

## 개인을 구분하지 않는다

- 브라우저/방문 세션 식별값을 발급·수집하지 않는다. 계정·게스트 쿠키와 연결하지 않는다.
- 이벤트 속성은 허용 목록의 게임·이벤트 이름·완료 상태뿐이며, 원래 방/라운드 ID·시드·단어·채팅·닉네임·이메일·URL·유입 경로·기기 상세는 거부한다.
- 중복 방지용 임의 판/이벤트 UUID만 서버로 보낸다. 다른 판과 사용자를 연결하는 공통 ID는 없다.
- 탭 저장소에는 현재 판 비교 정보와 중복 여부만 유지하고, 30분 무활동 뒤 새 판 번호를 쓴다. 저장소가 막혀 있으면 메모리만 사용하며 이 경우 새로고침 중복 방지는 보장하지 않는다.
- 기본값이 켜져 있어도 DNT/GPC 또는 개인정보처리방침의 수집 거부 설정은 반영한다. 게임 기능 제한은 없다. 로컬 영구 저장소에는 거부/재허용 선택 외의 측정 값을 기록하지 않는다.
- 서버 수신 시각과 한국 날짜를 사용한다. 원문 이벤트는 7일간 조회하고 매일 Cron에서 만료 데이터를 삭제한다. 백업은 기존 보관 정책을 따른다.
- 수집 중단은 대기열과 앞으로의 전송을 중단하며, 이미 수신했거나 진행 중인 전송을 즉시 철회하지 않는다.

**실제 이용자 수·회원 수·방문 세션 수·개인별 재방문율은 이 자료로 계산하지 않는다.** 날짜별 수치는 해당 측정 판의 첫 이벤트가 발생한 한국 날짜에 배정한다. 창 닫기·새로고침·거부 설정·신호·네트워크·차단 도구로 누락될 수 있다. 클라이언트 신고 수치라 보상·순위·운영 감사 근거로 쓰지 않는다.

## 서버와 비용

POST /api/product-metrics는 Worker의 인증 조회 이전에 별도로 처리하고 인증 쿠키를 검사하지 않는다. same-origin JSON, 6KB/12건 상한, Cloudflare IP의 날짜별 해시로 분당 60배치 제한을 적용한다. IP 원문은 이벤트에 저장하지 않고 제한 카운터는 기존 기술 만료 정책으로 정리한다.

주요 전환을 10초 간격으로 묶고 완료·화면 숨김 때 전송한다. credentials:omit + keepalive + 5초 제한시간을 적용한다. 실패 시 메모리 대기열 최대 60건·60초 재시도 간격을 두며 게임 입력과 화면 전환은 기다리지 않는다.

D1에는 배치당 제한 카운터 1회와 이벤트 INSERT만 추가한다. ID와 판/모드/이벤트 고유키로 재전송을 무시한다. 관리자 전용 /admin/metrics는 수동 갱신하며 식별번호를 반환하지 않는다. 대규모 유입 전에는 일별 집계 테이블과 비용을 별도 검토한다.

## 배포와 복구

1. 로컬의 별도 DB에서 제안된 0032_product_metrics.sql과 집계·만료를 검증한다. PR 검토 중 참여 방식과 스키마를 수정했으며, 최종 스키마를 2026-10-19 운영에 적용했다.
2. 운영 복구 지점을 확보한 뒤 독립 테이블·인덱스만 생성한다. 기존 계정·게임·재화 테이블은 수정하지 않는다.
3. 실제 구조를 확인한 뒤 deploy-schema.json 해시를 갱신한다. 2026-10-19 운영 구조를 확인한 뒤 배포 기준에 해시를 반영했다.
4. 배포 후 별도 브라우저에서 참여 클릭 없이 게임 진입·첫 조작·완료·재도전이 관리자 집계에 들어오는지 확인한다.
5. 거부/DNT/GPC, 관리자 권한과 일일 만료를 확인한다. 복구는 이전 코드 배포이며 새 테이블이나 기존 사용자 기록을 삭제하지 않는다.

#22는 계속 열어 둔다. 외부 신규 이용자 관찰, 로그인/기록 연결 실패, 빈 방 이탈, 신고 처리 시간, 기존 API 지연/요청 비용 연결과 실제 공개 기간 기준값이 남아 있다. 장기 개인별 재방문은 이번 기본 집계 범위에서 제외하며, 필요하면 별도 식별 설계와 정책 검토가 필요하다.

## 검증

자동 테스트에서 참여 클릭 없는 기본 집계, 장기·세션 ID 미발급/미전송, 거부/DNT/GPC, 같은 판 새로고침/되돌리기 중복, 첫 수 성공, 허용하지 않은 속성, 실제 SQLite 집계·보관 만료와 기존 골드 표본 보존을 확인한다. 운영 수집·운영 인증 화면·실기기 전 모드 확인과 로컬 자동 검사를 구분한다.
