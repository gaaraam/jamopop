# 제품 지표 1차 — #22

## 측정 질문

게임별로 들어온 판 중 첫 조작까지 진행하는가? 직접 플레이한 판을 끝내는가? 그 뒤 재도전하거나 다른 판을 여는가?

- 대상: 방 대전·연습·스피드전, 오늘의 단어, 단어 도전, 콩알 탈출, 자모 쏙쏙, 자모 톡톡.
- 진입 화면: 첫 화면·대기실·개인 도전 목록. 화면별 방문 세션을 별도로 표시한다.
- `view`: 실제 플레이 화면/복원 상태가 로드됨. 탭 세션에서 같은 판의 반복 조회는 중복 집계하지 않는다.
- `start`: 플레이 화면에서 진행 중인 판을 확인함. 저장된 진행 중 판도 포함한다. 방의 시작 대기 시간을 일부 포함할 수 있으므로 ‘진행 중 진입’은 즉시 입력 가능 시간의 측정이 아니다.
- `first_action`: 화면 로드 뒤 첫 유효한 이동/타일 선택 또는 서버가 수락한 첫 제출. 입력 글자·클릭 좌표·제출 원문은 보내지 않는다.
- `complete`: 위 첫 조작이 확인된 동일 판이 성공·실패·시간 종료·포기로 바뀜. 첫 조작 없이 복원한 완료 결과는 새 완료가 아니다. 판당 한 번만 센다. 되돌리기로 다시 끝내도 중복되지 않는다.
- `retry`/`next`: 직접 플레이했던 판 뒤 같은 판 재시작/다른 판 선택. 방·연습·스피드전은 다음 라운드를 실제로 관찰한 시점이다. 방장의 시작 버튼 클릭 수를 뜻하지 않는다.
- 완료율 = 같은 브라우저·탭 세션·판에서 `start`와 `first_action`이 확인된 `complete` / `first_action`.
- 관전, 폴링, 단순 키 입력, 조작별 이벤트, 광고, 회원 전적·재화 계산은 대상이 아니다.

## 표본과 식별

참여 기본값은 끔이다. 모든 공개 화면 아래 ‘플레이 흐름 측정’에서 선택한다. DNT/GPC가 켜져 있거나 로컬 저장소를 쓸 수 없으면 수집하지 않는다. 동의를 켜기 전 행동을 소급 전송하지 않는다.

- `visitor`: 로컬 저장소의 임의 UUID, 발급 후 7일에 교체. 계정·게스트 쿠키·이메일·닉네임과 연결하지 않는다.
- `session`: 탭 세션 저장소의 임의 UUID. 30분간 측정 이벤트가 없으면 교체. 다른 탭은 별도 세션이다.
- `run`: 측정 전용 임의 UUID. 원래 방/라운드 ID·시드·단어를 서버 이벤트에 넣지 않는다. 복원 비교에 필요한 키는 탭 세션 안에서만 사용한다.
- `id`: 이벤트 전송 재시도 중복 방지용 UUID.
- 이벤트 이름·게임 모드·완료 상태는 허용 목록으로 제한. 자유 입력 속성과 URL/유입 경로/기기 상세는 거부한다.
- 서버 수신 시각과 한국 날짜를 사용한다. 클라이언트 시각이나 점수는 받지 않는다.

재방문 브라우저는 선택 기간 내 **서로 다른 한국 날짜**에 이벤트가 있는 브라우저다. 실제 사람/회원/7일 이후 재방문을 의미하지 않는다. 전체 이용자 수나 회원 가입 전환율로 해석하지 않는다.

탈퇴·로그아웃과 별개의 선택적 측정이다. 참여 중단 시 로컬 식별값과 전송 대기열을 지우며, 이미 수신한 이벤트와 진행 중 전송은 즉시 철회되지 않는다. 이벤트는 수신 후 7일간 조회되고 일일 Cron에서 삭제한다. 기존 백업의 보관 기간은 별도다. 계정과 연결하지 않아 계정 삭제로 이벤트를 검색할 수 없다.

## 서버와 비용

`POST /api/product-metrics`: Worker의 인증/게임 안전 처리 이전에 별도로 처리해 계정 조회를 하지 않는다. same-origin JSON만 허용, 6KB/12건 상한, Cloudflare IP 일별 해시로 분당 60배치 제한. IP 원문은 이벤트에 저장하지 않는다. 제한 카운터는 기존 기술 만료 정책으로 정리된다.

주요 전환만 10초마다 묶고 완료·화면 숨김 때 전송한다. 전송은 자격 증명 없이 `keepalive`로 보낸다. 실패 시 최대 60건의 메모리 대기열과 60초 재시도 간격을 두며 게임 입력·화면 전환을 기다리게 하지 않는다. 페이지 종료 때 전송 성공은 보장하지 않는다.

D1에 배치당 제한 카운터 1회와 이벤트별 INSERT만 추가한다. 같은 이벤트 ID와 동일 방문/판/이름 고유키로 중복 전송을 무시한다. `/admin/metrics`는 수동 갱신만 하며 원문 식별자 없이 집계만 반환한다. 집계는 7일 원문 조회이므로 대규모 유입 전에는 일별 집계 테이블/비용을 별도 검토한다. 위조 가능한 클라이언트 표본이며 순위·보상·운영 감사 근거로 쓰지 않는다.

## 배포와 복구

1. 로컬에서 `0032_product_metrics.sql` 및 집계·만료 테스트를 확인한다.
2. 운영 DB 복구 지점을 확보한 후 새 테이블/인덱스만 생성한다. 기존 계정·플레이·재화 테이블은 수정하지 않는다.
3. 실제 테이블 구조를 검증한 뒤에만 `deploy-schema.json`에 해시를 추가한다. 이번 PR은 운영 DB 미적용 상태이므로 배포 기준을 미리 갱신하지 않는다.
4. 코드 배포 후 별도 테스트 브라우저에서 참여 → 게임 진입 → 첫 조작 → 완료 → 재도전이 관리자 집계에 들어오는지 확인한다. 테스트 표본은 실제 이용자와 구분해 기준값을 정한다.
5. 미동의 요청 없음, 관리자 외 조회 거절, 신규 이벤트 만료 Cron을 확인한다.
6. 복구는 이전 코드 배포. 새 독립 테이블은 유지해도 기존 서비스에 영향이 없다. 코드 롤백을 위해 테이블이나 기존 사용자 기록을 삭제하지 않는다.

운영에 수집되기 전의 과거 이용 흐름은 복원할 수 없다. 이 PR만으로 #22 전체를 완료하지 않는다. 외부 신규 이용자 관찰, 로그인/기록 연결 실패, 빈 방 이탈, 신고 처리 시간, 요청 비용의 제품 화면 연결 및 실제 공개 기간 기준값 측정은 후속 범위다. 기존 API 지연/쿼리량 로그와 제품 전환을 구분한다.

## 이번 검증

- 자동 검사: 포맷·공개 소스 검사·217개 테스트·타입 검사·프로덕션 빌드 통과.
- 새 SQLite 테이블에서 중복 ID/의미 중복, 같은 판의 첫 수 성공, 결과 복원, 되돌리기, 다른 한국 날짜 재방문, 원문 속성 거부, 보관 만료를 검증했다. 기존 기록/골드 표본은 그대로 유지된다.
- 분리된 로컬 D1에서 전체 마이그레이션을 적용했다. 새 브라우저의 미동의 상태 0건 → 참여 후 자모 톡톡 진입/첫 조작 각 1건 → 오늘의 단어 실제 자판 제출·성공 완료 각 1건을 확인했다. 완료 화면을 새로고침해도 완료는 1건이다.
- 운영 계정·DB에서 수집을 시작하거나 운영 데이터를 정리하지 않았다. 관리자 인증을 적용한 실제 운영 화면과 실기기 전 모드 검증은 아직 하지 않았다.
