# 플레이 접근성 점검 (#18)

> 2026-10-18 후속: 운영자 요청에 따라 소규모 베타 완료 기준을 [베타 운영 기준](beta-readiness.md)으로 재조정했습니다. 아래는 과거 구현·검증 이력이며, 현재 남은 범위는 해당 문서와 후속 #49/#50/#51을 따릅니다.

## 이번 변경

- 공통 게임판/자판과 개인 도전에 색 외 판정 표식(✓ / • / −) 제공.
- 자판과 개인 도전 타일에 자모·판정 이름을 제공. 표식은 중복 낭독하지 않음.
- 개인 도전 자판의 Enter/Space 활성화는 버튼 포커스를 유지. 마우스 클릭은 기존 입력 복귀 유지.
- 입력/자판/결과 행동의 키보드 포커스 표시, 터치 자판 최소 높이 44px, 모션 줄이기 적용.
- 서버 판정·저장·보상·DB 변경 없음.

## 확인한 범위

로컬 브라우저에서 밝은/어두운 테마의 오늘의 단어 결과에 모든 판정 표식을 확인했습니다. 개인 도전 시작 후 자판 버튼을 Enter로 활성화하면 자모가 1회 입력되고 버튼에 포커스가 유지되는 것을 접근성 트리에서 확인했습니다. 테스트와 빌드 결과는 PR에 기록합니다.

## 남은 검증 (이슈 전체 완료로 처리하지 않음)

- 실제 iOS Safari/Android Chrome의 5·6·7칸, 일반/아이템/스피드/개인 도전 완주.
- 실제 IME 조합, 채팅 전환, 외장 키보드, 화면 읽기 도구 검증.
- 작은 화면/엑셀 모드의 표식과 자모 간격, 느린 연결, 제출 버튼 가림 확인.
- 대비 수치와 시스템 모션 줄이기 설정을 켠 기기의 실제 효과 확인.

브라우저 레이아웃 검증을 실제 휴대폰 검증으로 보고하지 않습니다.

## 2026-10-18 후속 보강

- 녹색 판정 배경은 유지하고 작은 판정 표식·자모의 잉크를 #071e15로 변경. 밝은/어두운 녹색 기준 대비 6.72:1 / 4.53:1. 밝은 회색은 #43516a(5.31:1), 어두운 회색은 기존 #d5deeb(5.84:1)을 유지한다. 색별 대표 CSS 팔레트 계산이며 모든 UI 요소의 WCAG 적합 판정은 아니다.
- 모바일 게임/개인 도전 자판 높이 44px 하한 유지. 화면에 맞춰 칸 수·기회 수를 바꾸지 않는다.
- 채팅 visualViewport 계산은 핀치 확대를 시스템 자판으로 오인하지 않는다. focusout에서도 높이를 갱신하고 effect가 등록한 동일 DOM 노드에서 이벤트를 해제한다.
- 모션 줄이기에서 기존 Three.js 효과 생성 제한에 더해 효과 레이어를 숨긴다. 공유 상태·타이머·제출은 변경하지 않는다.
- `tests/chat-viewport.test.mjs`는 Safari 스크롤 오프셋·포커스 해제·음수 방지·핀치 확대·잘못된 높이를 검증한다. 기존 input/chat shortcut/word timer/모드별 테스트를 전체 CI에 포함한다.

### 실기기 인수표

아래는 **미완료**이며 기기 접근 없이 통과 표시하지 않는다. 각 기기에서 한글 조합 Enter, 5/6/7칸, 일반/아이템/스피드/개인 도전, 채팅 전환/전송 후 포커스, 회전·주소창 높이 변경, 재접속, 밝은/어두운 테마를 확인한다.

| 환경 | 실제 기기 | 남은 확인 |
|---|---|---|
|iOS Safari|미실시|시스템 자판 중복, IME 229, visualViewport, VoiceOver, 제출 가림|
|Android Chrome|미실시|IME Enter, 뒤로 가기/키보드, 채팅 포커스, TalkBack|
|데스크톱 375/390px 임베드|레이아웃 관찰용|coarse pointer·실제 모바일 입력과 동일하지 않음|

작은 화면 캡처만으로 실제 폰 검증을 대신하지 않는다. 운영 대화·플레이 기록을 테스트 목적으로 변경하지 않는다.

### 추가 실행 증빙

2026-10-18 최종 후보의 실제 렌더링 스타일을 확인했다. 개인 도전의 초록 자판이 후순위 solo.css에 덮여 흰 글자로 남는 문제를 발견해 공통 판정 잉크 우선순위를 수정했다. 수정 후 브라우저 computed style에서 초록 타일·키 모두 background rgb(100,175,148), color rgb(7,30,21)을 확인했다. 다크 회색은 background rgb(70,82,100), color rgb(213,222,235)로 확인했다.

로컬 개인 도전에서 사전 거절 후 ㄱㄱㄱㄱㄱ 초안 유지, 서버 연결 중단 후 새로고침 복원, 사과 Enter 제출→판정·자판 반영을 확인했다. 375×812/390×844 CSS viewport의 6행 보드에서 자판과 제출 버튼이 화면에 들어오는 것을 관찰했다(증빙은 화면 배율 80%로 두 viewport를 함께 촬영). 포인터·IME·화면 읽기 도구를 실제 모바일로 검증한 결과는 아니다.

별도 합성 HTTP 흐름으로 일반/아이템 각각 5·6·7칸의 사전 제출·판정 길이·정답 비노출·재전송 409·재조회 한 줄 보존, 스피드전 시작→카운트다운→제출→중복 revision 409를 확인했다. 브라우저 완주/실기기 인수와 구분한다.


## 타일 직접 입력 (2026-10-18)

- 별도 단어 입력창은 화면에서 숨기고, 현재 타일에 입력과 커서를 표시한다. 화면 자판과 초록·노랑·회색 판정은 유지한다.
- `GameInput`의 실제 input은 한글 IME, 붙여넣기, 화면 읽기 도구를 위해 유지한다. 게임판 클릭 시 포커스하되 터치 휴대폰에서는 시스템 자판을 열지 않는다.
- 공통 적용: 방/연습, 첫 판 체험, 오늘의 단어, 스피드전, 개인 도전. 자모 삭제·선택 영역 교체는 `editTileDraft`에서 처리한다.
- 페이지 자체에 포커스가 있을 때만 키를 게임 입력으로 전달한다. 채팅·설정·다른 버튼의 키보드 동작을 가로채지 않는다. 기존 백틱 채팅 토글을 유지한다.
- 단어 거절 시 입력 유지, 조합 중 Enter/229 및 조합 종료 직후 제출 차단은 기존 제출 경로를 사용한다. 서버/DB/판정 변경 없음.
- 검증: 공통 컴포넌트의 격리 Chromium 브라우저에서 타이핑·삭제·채팅 분리·타일 클릭·거절 후 초안·합성 composition 이벤트·모바일 자판을 확인했다. 실제 휴대폰/OS 한글 IME 검증과 구분한다.


### 타일 입력 확장 검증

`tests/browser/tile-input.mjs`는 로컬 서버에만 연결하며 별도의 게스트와 QA 방을 생성한다. Playwright가 설치된 환경에서 빌드 및 로컬 DB를 준비하고 로컬 서버를 실행한 뒤 다음과 같이 실행한다.

```sh
TEST_BASE_URL=http://127.0.0.1:5230 node tests/browser/tile-input.mjs
```

별도 설치 경로를 사용할 때는 `PLAYWRIGHT_MODULE`에 Playwright 모듈의 절대 경로를 지정한다. Chrome이 설치되어 있어야 한다. 실패한 항목이 있으면 종료 코드 1을 반환한다.

2026-10-18 로컬 최종 빌드에서 16개 브라우저 시나리오 통과:

- 방 5/6/7칸 입력, 초과 안내, 전체 선택 후 교체
- 오늘의 단어/개인 도전/첫 판 체험에서 화면 자판 클릭 후 물리 키보드 이어 쓰기
- 백틱 채팅 전환, 채팅 전송 후 포커스, 설정 입력 분리
- 사전 거절 후 초안 유지, 합성 IME 조합 중 Enter 및 종료 직후 Enter, Enter 연타의 단일 요청, 새로고침 복구
- 서버 503 후 초안 유지, 지연 응답 중 채팅 포커스 유지
- 첫 판 체험 3개 단어 완주와 다크 테마의 초록/노랑/회색 자판 구분
- 스피드전 카운트다운 후 입력
- PC 1280px, 작은 창 768/600px, 휴대폰 390px: 자판 유지, 숨긴 입력 영역 크기, Enter 버튼 활성화 시 포커스 유지, 모바일 inputMode

검증에서 발견한 첫 판 체험의 마우스 클릭 후 입력 단절과 엑셀 모드의 옛 입력창 너비 규칙 충돌을 수정했다. 기존 엑셀 화면 최소 너비는 620px이므로 600px 창의 가로 스크롤 20px은 유지된다. 실제 OS 한글 IME와 실기기 검증은 여전히 별도이며, 이 결과를 해당 검증 완료로 해석하지 않는다.
