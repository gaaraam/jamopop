# 가입 승인과 개인 이용

- 게스트: 개인 도전·오늘의 단어만 플레이. 방·회원·채팅·초대·친구 조회와 참여 불가.
- 신규 Google 회원: 기본 승인 대기. 개인 게임, 내 집 돌보기, 꾸미기, 문의·계정 관리 이용 가능.
- 관리자 승인 뒤: 방과 커뮤니티 이용 가능. 재로그인 없이 다음 요청부터 적용.
- 거절: 개인 기능 유지, 문의 가능. 관리자가 거절 목록에서 재승인 가능.
- 기존 회원: 0034 적용 시점의 Google 계정을 승인으로 유지. 사용자 기록·골드·스킨·연결 관계는 변경하지 않음.

## 구현 경계

검증된 Google 세션 조회에 승인 상태를 함께 읽는다. 클라이언트가 보낸 신원·승인 헤더는 Worker에서 제거한다. 승인 상태는 Google 계정에 귀속되어 게임 프로필 전환이나 Sites 기록 연결로 상승하지 않는다. 관리자 계정은 승인 화면에 접근할 수 있다.

Worker의 개인 API 허용 목록 밖의 요청은 비승인 사용자에게 403. 방 링크·관리자 페이지는 개인 게임 화면으로 안내한다. 내 정보의 과거 방 목록·방 기록, 내 집의 친구·방문자 이름도 비승인 사용자에게 반환하지 않는다. 화면의 버튼 숨김에 의존하지 않는다. 새 API를 추가하면 공개 범위를 이 목록과 함께 검토한다.

운영 → 가입 승인(`/admin/approvals`)에서 대기·승인·거절 목록 확인. 승인·거절은 관리자, 동일 출처, 계정별 revision 검증 뒤 처리한다. 이미 처리한 신청의 중복 결정은 409이며 검토자·시간을 저장한다. 가입 승인은 이용 정지와 별개이고 기존 신고·이용 제한은 계속 적용한다.

## 배포

D1 복구 지점 확보 → 0034 적용 → 기존 회원 수와 승인 수/기존 기록 수 확인 → deploy-schema.json 해시 갱신 → 코드 배포. 마이그레이션 이후 신규 가입은 pending 기본값이다. SQL을 다시 실행하지 않는다. 이전 코드로 롤백하면 새 열은 남지만 접근 제한은 해제되므로 운영 판단이 필요하다.

## 검증

마이그레이션 전·후 회원, 신규 회원 기본값, 신원 헤더 위조, 방/회원 API GET·POST, 세션 승인 반영, 프로필 전환, 관리자 승인·중복·타인 계정 보존, 내 정보/집 응답 정보 제한을 자동 테스트한다. 운영에서 임의 회원을 승인하거나 테스트 계정을 생성하지 않는다.
