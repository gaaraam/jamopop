# 자음모음팝 · Jamopop

**같은 방에서 같은 단어를 추리하는 한글 멀티플레이 게임.**

자음·모음을 입력하고 초록·노랑·회색 단서로 정답을 찾아갑니다. 함께 풀고, 채팅하고, 응원을 보내며 나만의 **콩알친구들** 캐릭터를 꾸밀 수 있습니다.

[게임 시작하기](https://play.jamopop.workers.dev/) · [버그 제보·기능 제안](https://github.com/gaaraam/jamopop/issues) · [기여 안내](CONTRIBUTING.md)

## 어떤 게임인가요?

기본 문제는 **자모 5칸, 다섯 번의 시도**로 진행합니다. 5칸은 한글 다섯 글자가 아니라, 단어를 풀어 쓴 자음·모음의 수입니다. 예를 들어 `바람`은 `ㅂ ㅏ ㄹ ㅏ ㅁ`입니다.

| 판정 | 의미 |
| --- | --- |
| 🟩 초록 | 정답에 있고 위치도 일치 |
| 🟨 노랑 | 정답에 있지만 위치가 다름 |
| ⬜ 회색 | 해당 자모가 없거나, 정답에 있는 개수를 초과 |

대기실에서 방을 만들거나 참여하면 같은 문제를 함께 풉니다. 기본 방 제한시간은 **5분**이며, 참가자의 진행 상황을 실시간으로 볼 수 있습니다. Google 계정으로 로그인하거나 게스트로 시작할 수 있습니다.

## 플레이 모드와 기능

| 구분 | 내용 |
| --- | --- |
| **일반전** | 같은 정답을 두고 시도 횟수와 완료 기록으로 경쟁 |
| **아이템전** | 공격·방어·시간 보조 아이템을 사용하는 방 대전 |
| **스피드전** | 주제별 문제 묶음을 연속으로 푸는 모드 |
| **개인 도전** | 단어가 사라진 건물을 한 층씩 복구하는 스테이지 도전 |
| **함께하기** | 방·대기실 채팅, 친구, 방 초대, 응원, 그림 힌트, 관전 |
| **성장·꾸미기** | 경험치와 레벨, 상황별 칭호, 골드, 콩알친구들 캐릭터와 스킨 |

다크 모드와 작은 창에서 사용하는 엑셀 형태의 미니 모드도 지원합니다. 운영 화면에서는 회원·게스트 활동, 문의, 전체 공지를 관리합니다.

## 로컬에서 실행하기

**Node.js 24와 npm, Git**이 필요합니다. 운영 계정이나 Cloudflare 토큰 없이 로컬 게스트 플레이를 시작할 수 있습니다.

```sh
git clone https://github.com/gaaraam/jamopop.git
cd jamopop
npm ci
npm run dev
```

브라우저에서 **http://127.0.0.1:5173** 을 엽니다.

첫 실행은 다음 순서로 진행되므로 잠시 시간이 걸립니다.

1. 앱을 빌드합니다.
2. 로컬 D1에 아직 적용되지 않은 SQL을 적용합니다.
3. Wrangler 로컬 서버를 실행합니다.

**현재 `npm run dev`는 자동 새로고침 개발 서버가 아닙니다.** 소스를 수정한 뒤에는 서버를 종료하고 같은 명령으로 다시 실행해 주세요. 로컬 데이터는 `.wrangler/state`에 유지됩니다.

Google 로그인과 기존 Sites 기록 연결은 운영 도메인에 연결되어 있습니다. 기본 로컬 환경에서는 게스트로 확인하고, 인증·기록 이전 로직은 관련 테스트를 이용해 주세요. 로컬 개발을 위해 운영 DB나 로그인 비밀키를 연결할 필요는 없습니다.

## 자주 쓰는 명령

| 명령 | 용도 |
| --- | --- |
| `npm run dev` | 빌드 → 로컬 DB 준비 → 5173 포트에서 실행 |
| `npm run ci` | 공개 소스 검사 → 테스트 → 타입 검사 → 빌드 |
| `npm test` | 게임 규칙·입력·복구·기록 이전 등의 자동 테스트 |
| `npm run typecheck` | TypeScript 타입 검사 |
| `npm run build` | 배포용 앱과 Worker 설정 생성 |
| `npm run db:local` | 빌드된 설정을 사용해 로컬 DB에 미적용 SQL 적용 |

PR을 올리기 전에는 다음 명령을 실행해 주세요.

```sh
npm run ci
```

화면이나 입력을 수정했다면 브라우저에서도 직접 확인해 주세요. 자동 테스트만으로 한글 조합 입력, 모바일 키보드, 채팅 포커스 등 모든 사용 흐름을 검증할 수는 없습니다.

## 코드 살펴보기

프런트엔드는 **React + TypeScript**, 빌드·실행은 **Vinext + Vite**, 운영 서버와 데이터 저장은 **Cloudflare Workers + D1**을 사용합니다. DB 스키마는 Drizzle과 SQL 마이그레이션으로 관리합니다.

```text
app/                페이지, API 경로, 스타일
components/         화면 컴포넌트
hooks/              공통 React 훅
lib/                게임 규칙, 입력, 동기화, 계정, 보상·꾸미기 로직
db/                 DB 스키마와 연결 코드
drizzle/            SQL 마이그레이션
public/             캐릭터·스킨 등 정적 파일과 사전 데이터
tests/              게임 및 기록 이전 테스트
scripts/            로컬 실행, 공개 소스 검사, 배포 스크립트
build/              Cloudflare Worker 진입 코드
docs/deployment.md  배포 설정과 DB 변경·롤백 절차
```

작업을 시작할 때 참고할 파일:

- **판정·순위:** [lib/game.ts](lib/game.ts)
- **한글 입력:** [lib/input.ts](lib/input.ts)
- **조회·동기화 주기:** [lib/sync-policy.mjs](lib/sync-policy.mjs)
- **캐릭터·스킨:** [lib/companions.ts](lib/companions.ts), [lib/skins.ts](lib/skins.ts)
- **개인 도전:** [lib/solo.ts](lib/solo.ts), [lib/solo-story.ts](lib/solo-story.ts)

## 함께 개발하기

작은 버그 수정, 모바일 사용성 개선, 게임 아이디어 모두 환영합니다. 큰 변경은 먼저 Issue에서 방향을 맞춰 주세요.

1. 저장소를 포크하거나 작업 브랜치를 만듭니다.
2. 로컬에서 수정하고 `npm run ci`를 실행합니다.
3. PR에 **문제·변경 내용·확인 방법**을 적습니다. UI 변경은 전후 화면도 첨부해 주세요.
4. 운영자가 검토한 뒤 직접 병합합니다. 기본 병합 방식은 **Squash and merge**입니다.

진행 중인 판과 기존 사용자 기록을 보존하는 것이 우선입니다. 특히 한글 조합 입력, 중복 제출, 재접속, 서버의 점수·재화·권한 판정을 바꿀 때는 관련 테스트를 함께 확인해 주세요.

자세한 규칙은 [CONTRIBUTING.md](CONTRIBUTING.md), 보안 문제 제보 방법은 [SECURITY.md](SECURITY.md)를 참고해 주세요. 실제 사용자 정보·채팅·쿠키·토큰·DB 백업은 Issue나 PR에 올리지 마세요.

## 배포 흐름

```text
작업 브랜치 → PR 검토 → 운영자가 main에 병합
                         ↓
                Cloudflare Workers Builds
                공개 소스 검사 · 테스트 · 타입 검사 · 빌드
                         ↓ 모두 성공
                play.jamopop.workers.dev
```

- 자동 배포는 **Cloudflare**가 담당합니다. GitHub Actions는 수동 검사 용도로만 남아 있습니다.
- 자동 검사는 현재 **main 병합 후, 배포 전**에 실행됩니다. PR 단계의 자동 검사 통과를 보장하는 구성은 아닙니다.
- 검사·빌드가 실패하면 기존 배포가 계속 서비스됩니다.
- 운영 DB 마이그레이션은 자동 실행하지 않습니다. SQL 변경은 별도 운영 적용 절차가 필요합니다.

배포 환경 변수, 인증 정보, 스키마 변경 및 롤백은 [배포 문서](docs/deployment.md)를 확인해 주세요.

## 데이터와 라이선스

이 저장소에는 운영 DB, 사용자 기록, 로그인 비밀키가 포함되어 있지 않습니다. 기존 Sites 기록 연결 기능은 운영 서비스의 계정 이전 기능이며, 저장소를 복제해도 사용자 데이터가 내려오지 않습니다.

사전 데이터의 출처와 이용 조건은 [NOTICE.txt](public/dictionaries/NOTICE.txt)와 [SOURCE.txt](public/dictionaries/SOURCE.txt)를 확인해 주세요.

**프로젝트 전체에 적용할 오픈소스 라이선스는 아직 정하지 않았습니다.** 저장소 공개가 코드·캐릭터·스킨의 자유로운 재배포나 상업적 사용 허가를 뜻하지는 않습니다.
